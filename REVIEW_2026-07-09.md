## 5. Обзор архитектуры проекта

### 5.1 Общая структура

```
survival_map/
├── parser/          # Telegram парсер (pyrogram → NLP → PostGIS)
├── core/            # aiohttp REST + WebSocket (JWT, rate-limit)
├── web/             # Leaflet PWA (TypeScript, webpack)
├── postgres/        # PostGIS + init-скрипты
├── scripts/         # Утилиты экспорта/анализа
├── tests/           # pytest
└── docker-compose.yml
```

### 5.2 Микросервисы

| Сервис | Технология | Назначение |
|--------|-----------|-----------|
| **postgres** | PostgreSQL 16 + PostGIS | Хранение газеттира и событий |
| **parser** | pyrogram + ONNX BERT + pymorphy3 | Парсинг Telegram → геолокация |
| **core** | aiohttp + asyncpg | REST API + WebSocket + JWT |
| **web** | nginx + Leaflet + MapLibre GL | PWA фронтенд |

### 5.3 Pipeline геолокации

```
Telegram message
  → LayerClassifier (ключевые слова)
  → GeoMatcher (3-tier fuzzy)
    Tier 1: surface fuzzy (token_sort_ratio)
    Tier 2: surface typo (ratio, DL 1-2)
    Tier 3: lemma fuzzy (fallback)
  → TypeValidator (ONNX rubert-tiny2, zero-shot)
  → SemanticResolver (qwen2.5:0.5b, опционально)
  → process_candidates (PostGIS)
    → single_match / intersection / midpoint / area
  → INSERT INTO events (ON CONFLICT dedup)
  → pg_notify → WebSocket → frontend
```

### 5.4 Сильные стороны архитектуры

1. **Изоляция сетей** — `db` network internal-only, `frontend`/`backend` разделены
2. **Безопасность** — non-root контейнеры, drop ALL capabilities, tmpfs
3. **Идемпотентность** — ON CONFLICT делает повторную обработку безопасной
4. **Graceful shutdown** — parser drain очереди 20s, core WebSocket drain
5. **Offline-first PWA** — service worker + localStorage кэш
6. **Параметризованный SQL** — инъекций нет
7. **Multi-stage Docker** — core: 368MB → 163MB (-56%)
8. **TTL очистка** — pg_cron каждые 5 мин, events > 1 hour
9. **JWT + HMAC** — Telegram initData validation (constant-time)
10. **Self-heal WebSocket** — jitter, visibility reconnect, snapshot warning

### 5.5 Слабые стороны и риски

| Проблема | Приоритет | Описание |
|----------|-----------|----------|
| Нет автотестов | **P0** | Python и JS — 0 unit-тестов покрывают критичную логику |
| TypeScript strict: false | **P1** | noImplicitAny/strictNullChecks отключены |
| Rate-limit spoofing | **P0** | XFF без trusted source → обход квоты |
| Path-traversal в media | **P0** | symlink не отсекается, утечка путей |
| JWT-кэш | **P1** | ключ = сырой токен, TTL 60с без отзыва |
| single-process parser | **P1** | bottleneck при масштабировании |
| Нет TLS | **P0** | nginx без HTTPS, только :80 |
| Нет мониторинга | **P1** | Prometheus экспортирует, но нет сборщика |
| Нет бэкапов | **P1** | pg_dump не настроен |
| Дрейф документации | **P2** | docs/web.md описывает «MapLibre native» (реально Leaflet) |

### 5.6 Рекомендации по развитию

**Краткосрочные (неделя 1-2):**
1. Добавить pytest-набор на критичную логику (street_matcher, process_candidates, telegram_validation)
2. Включить TypeScript strict mode (минимум strictNullChecks)
3. Исправить rate-limit spoofing (nginx set_real_ip_from)
4. Убрать лишние capabilities у web (CHOWN, SETGID, SETUID, DAC_OVERRIDE)

**Среднесрочные (неделя 3-4):**
5. Добавить Prometheus + Grafana
6. Настроить TLS/SSL (Let's Encrypt или Cloudflare Tunnel)
7. Добавить pg_dump cron для бэкапов
8. Расширить газеттир (6 отсутствующих локаций)

**Долгосрочные (неделя 5+):**
9. Kubernetes миграция для масштабирования
10. Распределённый кэш (Redis вместо in-memory LRU)
11. Parser partitioning (несколько instances)
12. Distributed tracing (Jaeger/Zipkin)
