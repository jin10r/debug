## 2. Распределение по стратегиям

| Стратегия | Старые экспорты | Новый экспорт | Изменение |
|-----------|----------------|---------------|-----------|
| `single_match` | 58 (46%) | 66 (60.6%) | **+14.6%** |

| `intersection` | 8 (6%) | 14 (12.8%) | **+6.8%** |
| `weighted_centroid` | — | 8 (7.3%) | **новый** |
| `centroid` (старый) | 22 (17%) | — | **удалён** |

| `proximity` | 2 (2%) | — | **удалён** |
| `area` | 2 (2%) | — | **удалён** |

### Выводы по стратегиям

1. **Удалены некачественные стратегии:**
   - `centroid` (старый) — простой центроид без учёта типов геометрий, заменён на `weighted_centroid` с разделением intersection/candidate points
   - `pseudo_intersection` — нестандартная стратегия, заменена на `street_segment` для линий или `weighted_centroid`
   - `proximity` — неточная стратегия для далёких объектов, заменена на `weighted_centroid`
   - `area` — редкая стратегия, заменена на `single_match`

2. **Рост `single_match` (+14.6%):** Более строгие пороги для пространственных гипотез (требуется `adjusted_score >= 0.85`) приводят к тому, что слабые пары, которые раньше давали `midpoint`/`proximity`, теперь корректно fallback в `single_match` или `random`.

3. **Рост `random` (+8%):** События с низкой similarity (<0.85), которые раньше получали стратегию по умолчанию (`midpoint`/`proximity`), теперь явно fallback в `random`. Это повышает прозрачность системы.

4. **Рост `intersection` (+6.8%):** Новый порог Option B (один кандидат >=0.95, второй >=0.80) позволяет корректно обрабатывать асимметричные совпадения, которые раньше терялись.

5. **`weighted_centroid` (7.3%):** Новая стратегия для компактных кластеров 2+ объектов с scatter ≤1500м. Использует два типа точек с разным весом (intersection ×2.5, candidate ×1.0) для более точного позиционирования.

## 6. Геометрия

| Тип геометрии | Старые экспорты | Новый экспорт | Изменение |
|---------------|----------------|---------------|-----------|
| POINT | ~80% | 48.6% | **-31.4%** |
| LINESTRING | ~10% | 37.6% | **+27.6%** |
| POLYGON | ~8% | 11.9% | +3.9% |
| MULTIPOLYGON | ~2% | 1.8% | -0.2% |

### Вывод
1. **Резкий рост LINESTRING (+27.6%):** Это связано с двумя факторами:
   - `street_segment` стратегия возвращает LINESTRING (пока 0 событий, т.к. нет линий с 2+ пересечениями)
   - `single_match` для линейных гео-объектов (улиц) теперь сохраняет исходную геометрию LINESTRING вместо центроида POINT
   
2. **Снижение POINT (-31.4%):** Положительная тенденция — меньше событий с центроидом полигона/линии, больше сохраняется исходная геометрия. Это improves точность отображения на карте.

3. **Устранение огромных полигонов:** В старых экспортах были полигоны городов размером ~68 KB (Ильичевск). В новом экспорте таких аномалий нет — для `single_match` используется `ST_MakeValid(geom)` без принудительного центроида.

## 9. Критические проблемы нового экспорта

### 9.1 Отсутствие `street_segment` событий
**Проблема:** Нет ни одного события со стратегией `street_segment`.  
**Причина:** В текущем наборе данных нет линий (LINESTRING), пересекающих 2+ объекта с segment ≤2000м.  
**Риск:** Стратегия не протестирована в боевых условиях.  
**Рекомендация:** Добавить тестовые данные с линиями, пересекающими объекты, или дождаться реальных событий.

### 9.2 Низкое фото покрытие (0.9%)
**Проблема:** Только 1 событие из 109 имеет фото.  
**Причина:** Системная — пользователи редко прикрепляют фото.  
**Влияние:** Не связано с гео-стратегиями.

### 9.3 22.7% низких similarity (<0.9)
**Проблема:** Почти каждый 4-й матч имеет similarity <0.9.  
**Причина:** Возможные опечатки, неполные совпадения, новые гео-объекты без алиасов.  
**Рекомендация:** Проанализировать пары с low similarity, добавить алиасы в `geo.csv`.
