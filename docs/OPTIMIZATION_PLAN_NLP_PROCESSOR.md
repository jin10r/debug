## Найденные проблемы

### Критичные (C)

| # | Проблема | Описание | Влияние | Источник |
|---|----------|----------|---------|----------|
| C1 | **GIL contention** | Весь NLP (tokenize, lemmatize, classify) выполняется синхронно в async event loop. 8 workers разделяют GIL — при нагрузке сериализуются | Снижение throughput на 40-60% | Код |
| C2 | **Ложные гео-матчи** | `"зелёного диктатора"` → `Зелёное` (ул.); `"с зелёными"` → `Зелёное`. Словоформы прилагательных матчатся как топонимы | Некорректная геолокация событий | Данные: id=105,196 |
| C3 | **Мусор в данных** | id=282: `❕` (только эмодзи); id=303: `слишком длинное сообщение не является релевантной локацией` — системное сообщение попало в events | Загрязняет базу, ложные POINT | Данные |

### Средние (M)

| # | Проблема | Описание | Влияние | Источник |
|---|----------|----------|---------|----------|
| M1 | **Sequential `_link_span`** | Каждый кандидат обрабатывается последовательно в `geo_matcher.py:295` | +2-3x для multi-candidate | Код |
| M2 | **Pool saturation** | 8 workers × polling + listen_conn = 9 concurrent pool acquisitions | Задержки при высокой нагрузке | Код |
| M3 | **12 regex substitutions** | `preprocess_light` применяет 12 Ukrainian suffix regex последовательно | +11 passes для UA текста | Код |
| M4 | **No batch processing** | Каждое сообщение — 3 roundtrips (fetch → insert → mark_done) | -60% roundtrips | Код |
| M5 | **Ошибка классификации слоёв** | `блокпост ❗️` → `cops`/`bus` вместо `traffic` (id=1,2,238); `пирожок` (транспорт) → `pig` вместо `bus` (id=71,91,114); смешанные `полиция + бус` → `bus` вместо `cops` (id=88,342) | Неправильная визуализация на карте | Данные |
| M6 | **single_match с несколькими кандидатами** | 29 событий (31%) имеют 2-5 matches, но strategy=single_match. Геометрия берётся от первого кандидата, остальные игнорируются | Потеря географического контекста | Данные |
| M7 | **Полигон Ильичёвска** | 6 разных событий (Средняя/Вишнёвая, Копейка, Парусная, 1 мая) → один полигон 44 вершин. Геометрия не релевантна для конкретного события | Некорректная визуализация | Данные: id=88,91,170,187,221,273 |

### Низкие (L)

| # | Проблема | Описание | Влияние | Источник |
|---|----------|----------|---------|----------|
| L1 | **Duplicate stopwords** | GeoMatcher и SemanticResolver загружают stopwords независимо | -1 DB roundtrip при старте | Код |
| L2 | **aiohttp session leak** | SemanticResolver создаёт новую `ClientSession` на каждый Ollama call | TCP overhead | Код |
| L3 | **Dead code** | `_sanitize_text()` определён, но нигде не вызывается | Чистота | Код |
| L4 | **pg_notify payload без geo_id** | Триггер `geo_updated` не передаёт `geo_id` → всегда полный reindex | -90% reindex work | Код |
| L5 | **`_random_point()` imports** | `import math, random` при каждом вызове | 2 импорта/msg | Код |
| L6 | **photo_url всегда пуст** | Ни одно из 94 событий не имеет photo_url. Поле не заполняется парсером | Нет привязки к фото | Данные |
| L7 | **Ложные match-стоп-слова** | `Стрюково` (микрорайон) не найден в gazetteer → random POINT. `Копейка` (магазин) матчится как локация | Мусорные гео-точки | Данные: id=152,228,187 |

## План оптимизации

### Фаза 1: Quick Wins + Data Quality (низкие усилия, высокий эффект)

| # | Что | Файл | Эффект | Ожидание |
|---|-----|------|--------|----------|
| 1.1 | Удалить мёртвый код `_sanitize_text()` | `processor/main.py:374-378` | Чистота | 5 мин |
| 1.2 | Кэшировать `import math, random` на уровне модуля | `processor/main.py` | Убрать 2 импорта/msg | 5 мин |
| 1.3 | Загружать stopwords один раз (общий для GeoMatcher + SemanticResolver) | `geo_matcher.py`, `semantic_resolver.py` | -1 DB roundtrip | 15 мин |
| 1.4 | Добавить `geo_id` в payload триггера `geo_updated` → targeted reindex | `postgres/06-notify-trigger.sql`, `processor/main.py:250` | -90% reindex work | 30 мин |
| 1.5 | Использовать `asyncio.to_thread` для CPU-bound NLP (tokenize, lemmatize, classify) | `processor/main.py:385-387` | Снять GIL contention | 30 мин |
| 1.6 | **Стоп-словосочетания для geo matching**: добавить `"зелёного"`, `"зелёными"`, `"зелёный"` в stopwords. Не матчить прилагательные как топоним `Зелёное` | `geo_matcher.py` (stopwords) | Убрать ложные срабатывания | 15 мин |
| 1.7 | **Фильтрация мусора**: отсеивать сообщения длиной < 3 символа, содержащие только эмодзи/спецсимволы, и системные сообщения (`не является релевантной локацией`) | `processor/main.py` (предобработка) | Не засорять базу | 15 мин |
| 1.8 | **Стоп-слова для не-гео**: `"копейка"` (магазин), `"шума"` (микрорайон Ильичёвска — не улица), `"рабина"` (АЗС WOG) — добавить исключения или приоритет | `geo_matcher.py` | Точнее гео-матчинг | 20 мин |

**Общий эффект:** ~40-60% increase throughput, cleaner code, -30% ложных гео-матчей
