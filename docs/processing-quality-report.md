## 2. 🔴 Баг, найденный и исправленный: фото не привязывались к событиям

**Симптом:** `photo_url = NULL` у 103 из 103 событий, хотя parser логировал `photo attached: /media/events/...jpg` и файлы реально качались на диск (4 шт.).

**Корень:** триггер `notify_photo_download()` (`postgres/init-scripts/10-pending-events.sql`) слал в NOTIFY `event_id = NEW.id` — это **id из таблицы `pending_events`**, а parser выполнял `UPDATE events SET photo_url WHERE id = <этот id>`. id двух таблиц не совпадают: для одного `message_id` `pending_events.id=29`, а `events.id=117`. UPDATE молча не находил строку → фото качались, но URL не записывался.

**Фикс:** триггер теперь резолвит настоящий `event_id` через `(message_id, event_time)`:
```sql
SELECT e.id INTO v_event_id FROM events e
WHERE e.message_id = NEW.message_id AND e.event_time = NEW.event_time;
```
Применён к живой БД + `docker restart parser` (догоняющий `_recover_missing_photos` привязал 4 фото). Новые фото будут привязываться автоматически.

## 4. 🟠 Проблемы пайплайна

### 4.1 `street_segment` не сработал ни разу (0/105)
Гипотеза требует линию, пересекающую **2+ других кандидатов** — на практике двухуличные события уходят в `intersection` (что правильно), а линия с 2+ пересечениями почти не встречается. Код мёртвый, но не вредный.

### 4.2 Заглушка «слишком длиннное сообщение…» (3 шт.)
- Опечатка «длиннное» видна пользователю в description.
- Длинное сообщение **полностью выбрасывается из гео**, хотя часто содержит локацию в середине.
- Это единственные «текстовые дубли» в выборке (3 одинаковых).

### 4.3 Подсветка улиц в попапах сломана
В `matches` пишется `matched_text` (143 вхождений), фронтенд читает `matched_part` (0 вхождений) — подсветка совпадений в попапах не работает.

### 4.4 Калибровка confidence
63 события (69% от non-random) с `confidence = 1.00` — «точный стем» всегда даёт максимум. 19 событий < 0.7 — это все 14 random + 5 двухуличных `weighted_centroid` (0.44–0.61, занижены формулой `avg*0.85 − scatter_penalty`). Порог 0.7 нигде в UI не используется.

## 5. Выводы

**Что работает хорошо:**
- Механика пайплайна чистая: 0 дубликатов, 0 ошибок очереди, 0 null-геометрий, полная обработка истории за ~3 мин.
- Фикс перекрёстков (b167f3d) подтверждён на боевых данных: intersection 1% → 22%, random 22% → 13%.

**Что требует внимания (по приоритету):**
1. 🟢 **Сделано в этой сессии:** фикс фото-триггера (photo_url теперь привязывается).
2. 🟠 Зонный фильтр (ложные пины за bbox: «зелёное», «Черноморка»).
3. 🟠 Починить `matched_part` (подсветка в попапах) и опечатку «длиннное».
4. 🟠 Справочник: «Туристическая», «Армейская», «Шевченко» без «пр.», дефисные имена («Жолио-Кюри»).
5. 🟡 House-number интерполяция для пинов на длинных улицах.
6. 🟡 Калибровка confidence (не 1.00 за точный стем; не занижать двухуличные wc).
