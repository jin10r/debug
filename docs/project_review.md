# Ревью проекта: известные проблемы и техдолг

> Дата: 2026-06-03. Находки проверены по фактическому коду. В конце — список
> того, что проверялось, но **не подтвердилось** (чтобы не плодить ложные баги).

Приоритет: **High** — чинить до прода · **Medium** — заметная фрагильность ·
**Low** — мелочи/харднинг.

---

## High

### H1. Перепутаны координаты у «7 пересыпская» — улица мислоцирована
`postgres/data/streets.csv:29`
```
7 пересыпская,POINT(46.532274 30.73274)
```
Формат файла — `POINT(lon lat)`. Здесь lon=46.5, lat=30.7 — невалидно для Одессы
(lon≈30.7, lat≈46.5), координаты переставлены местами. Все события на эту запись
ставятся в другую точку планеты. **Фикс:** `POINT(30.73274 46.532274)` (рядом с
корректной `7 Пересыпская` LINESTRING выше). Стоит прогнать весь CSV проверкой
`lon BETWEEN 30 AND 31 AND lat BETWEEN 46 AND 47`.

## Medium

### M1. Одно имя → несколько разных мест (риск мислокации)
`postgres/data/streets.csv`
Матчер нормализует имя через `clean()` (lowercase) и возвращает один `street_id`
на имя. Но в газеттире есть записи с одинаковым именем и **разной геометрией в
разных районах**:
- `МЕТРО` (46.557) / `метро` (46.448) — два магазина;
- `Инто-Сана` (46.406) / `Интосана` (46.432) — два филиала клиники;
- `Скейт-парк` (46.578) / `Скейтпарк` (46.480) — два парка;
- `Цирк` (46.427) / `цирк` (46.486); плюс кейс-дубли `Гагарина`, `Вузовский`,
  `Шишкина`, `Куяльник`, `Ибица` и т.д.

Событие «возле Метро» уедет в один из двух — какой повезёт. Автодедуп **опасен**
(склеит разные места), поэтому нужен ручной разбор: оставить более точные/частые,
остальные либо удалить, либо переименовать в различимые (`Метро (Пос. Котовского)`).

### M2. Блокирующие FS-операции в event loop при скачивании фото
`parser/monitoring.py:416-429`
`_download_photo` — корутина, но `Path(...).resolve()`, `target_dir.mkdir(...)`,
`final_path.relative_to(...)` выполняются **синхронно** в петле; в `to_thread`
вынесен только `download_media`. На событиях с фото — кратковременные стопы loop'а.
**Фикс:** обернуть валидацию пути+`mkdir` в `asyncio.to_thread`.

### M3. Один последовательный воркер — потолок throughput
`parser/monitoring.py:247` (`_worker_task = create_task(self._message_worker())`),
`:289`. Пайплайн CPU-bound (pymorphy3 + rapidfuzz), воркер один. При всплеске
канала очередь (`maxsize=1000`) копится → рост RSS. Сейчас приемлемо (поток низкий),
но это известный потолок (см. `docs/parser.md`). На будущее — `ProcessPoolExecutor`
для `find_streets` или несколько воркеров с общей очередью (дедуп по `message_id`).

### M4. Тесты гоняются только в Docker — нет pre-merge валидации
`parser/tests/` зависят от `mawo_razdel`/`mawo_pymorphy3`, которых нет на хосте, и
моков нет. Локально/в CI парсерные тесты не запустить — баги матчера видны только
после деплоя. **Фикс:** прогон тестов в parser-контейнере как CI-шаг
(`docker compose exec parser python -m pytest parser/tests/ -q`), либо лёгкие моки
токенизатора/морфологии для unit-уровня.

## Low

### L1. CSP допускает inline-скрипты на map.html
`nginx.conf:84` — `script-src 'self' https://telegram.org 'unsafe-inline'`.
`'unsafe-inline'` в **script-src** ослабляет защиту от XSS и несогласован с
маршрутом на `:72`, где его нет. Inline нужен для style (MapLibre), но не обязан
быть в script-src — стоит убрать из script-src (оставить в style-src).

### L2. Права session.session на хосте — 644
`parser/session.session` (в git не трекается). Содержит токены Telegram-сессии.
Рекомендация `chmod 600` уже добавлена в README; на сервере выставить обязательно.

### L3. Захардкоженные пароли postgres/redis
`core/settings.py` — `postgres/postgres`, `redis/redis`. Допустимо: контейнеры во
внутренней сети (`internal: true`), без port-mapping наружу. Зафиксировать как
осознанный trade-off; при выносе БД наружу — параметризовать.

### L4. Нет acquire-таймаута у пулов
`parser/db_adapter.py:46`, `core/db/db_base.py:68` — `create_pool` без `timeout`.
Параметры пула берутся из `settings.db` (это ок), но при исчерпании пула ожидающий
acquire блокируется бессрочно (есть только `command_timeout`). Добавить `timeout=`
на acquire/pool — мелкая страховка от старвейшна.

### L5. pg_notify — доставка без гарантий
Live-событие через `pg_notify` теряется, если listener в момент NOTIFY
переподключается. Влияние низкое: события persist в БД, фронт при (ре)коннекте
делает полный фетч и догоняет. Для надёжности — heartbeat/подтверждение листенера.

### L6. Непиннутый gcc в сборке парсера
`Dockerfile.parser` — `apt-get install -y gcc` без версии → не полностью
воспроизводимая сборка. Незначительно.

### L7. Мисномер PhoneticIndex
`parser/phonetic_index.py` — после удаления фонетики класс `PhoneticIndex`/
`PhoneticEntry` и имя файла вводят в заблуждение (теперь это surface+lemma индекс;
докстринг это признаёт, имя оставлено для обратной совместимости). Косметика;
переименование тронет импорты и тесты — делать отдельным рефактором.

## Проверено — НЕ подтвердилось (ложные тревоги чернового аудита)

- **«Рассинхрон настроек пула» / хардкод 2/10/30** — неверно: и
  `parser/db_adapter.py:50-52`, и `core/db/db_base.py:62-71` читают
  `settings.db.{pool_min_size,pool_max_size,command_timeout}`.
- **«Утечка WebSocket-соединений при исключении»** — неверно: `websocket_handler`
  снимает регистрацию в `finally` (`core/api/websocket.py:232-233`), плюс мёртвые
  соединения чистятся при бродкасте (`:79`).
- **«TTL ненадёжен из-за таймзоны»** — неверно: `events.event_time TIMESTAMPTZ`
  (`02-tables.sql:32`), сравнение `event_time < NOW() - INTERVAL '1 hour'`
  (`03-functions.sql:24`) идёт по абсолютным моментам и не зависит от session-tz.
  TTL корректен (pg_cron каждые 5 мин).
